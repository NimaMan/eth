# Token Update Publishers

This package now focuses on a lightweight notification path. The heavy
token/pool snapshots are written to Redis directly by the token manager,
so the Python side only needs to broadcast which token addresses changed
in the latest block.

## Components

1. **TokenUpdateCache (`token_update_cache.py`)**
   - Tracks the set of all seen token addresses and the subset touched in
     the most recent block.
   - No longer stores pool or scam metadata; consumers hydrate that data
     from Redis snapshots.

2. **TokenUpdateNotifier (`token_update_notifier.py`)**
   - Publishes just the address lists via ZeroMQ (PUB socket for block
     updates, REQ/REP for querying the latest lists).
   - External processors (e.g., the Rust mempool service) subscribe to
     the notifier, receive the updated addresses, and then fetch full
     snapshots from Redis.

3. **TradeSignalPublisher (`trade_signal_publisher.py`)**
   - Unchanged: handles signal delivery and execution acknowledgements.

## Flow

```
LiveTokenTracker
    └─> TokenUpdateCache (record addresses per block)
            └─> TokenUpdateNotifier (ZeroMQ broadcast)
                    └─> Rust mempool processor (hydrates snapshots from Redis)
```

This simplified design keeps the ZeroMQ payloads tiny and relies on the
Redis snapshots generated by `LiveBlockTokenProcessor` for detailed
token/pool state.
