# V2 Mode A Gas Benchmark 2026-05-19

Contract: `BaygusTradingVault`

Mode A:

```text
buy:
  ETH -> token through the vault
  no sell-router allowance after buy

emergency sell:
  approve exact token amount
  sell token -> ETH
  clear allowance
  send ETH to treasury
```

## Deltas

Local mock:

```text
vault_buy_extra = 97,001 - 83,249 = 13,752
mode_a_sell_extra_vs_preapproved = 117,752 - 45,673 = 72,079
approve_plus_preapproved_sell_reference = 28,708 + 45,673 = 74,381
mode_a_vs_approve_plus_sell_reference = 117,752 - 74,381 = 43,371
```

Mainnet fork:

```text
vault_buy_extra = 141,720 - 124,159 = 17,561
mode_a_sell_extra_vs_preapproved = 112,023 - 58,974 = 53,049
approve_plus_preapproved_sell_reference = 32,359 + 58,974 = 91,333
mode_a_vs_approve_plus_sell_reference = 112,023 - 91,333 = 20,690
```

The approve-plus-sell reference is a lower-bound execution comparison, not a
full two-public-transaction cost model. A real two-transaction flow also pays a
second transaction envelope/base fee and is nonce-blocked during an emergency.

## Interpretation

Mode A costs more than a sell with pre-existing allowance, as expected. On the
mainnet fork, the extra emergency-sell execution gas is about `53k`.

Against a separate approve plus sell, Mode A is roughly competitive on gas and
strictly better operationally for scam exits because approval and sell are
atomic in one top-level transaction. It avoids the public two-tx race where sell
is nonce-blocked behind approval.

For gas-rank planning, the emergency sell route should use the fork number as
the first estimate:

```text
estimated_gas_used = 112,000 to 135,000 before adding live safety margin
```

Use a conservative configured gas limit above the estimate until we have more
fork samples across token types.
